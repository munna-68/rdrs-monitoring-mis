# 2026-09-14

## RDRS Monitoring MIS — prototype built (one-shot build)

Built the full prototype from the brief in `~/workbuddy-ai/rdrs-monitoring-mis`.
Replaces the manual Excel consolidation step: officers submit activity data via a
web app, and the data exports back out in the existing Tracking sheet's exact
column format, plus an oversight dashboard.

### Stack as built
- Next.js 15.5.25 (App Router, TS), React 19, Tailwind v4.
- Drizzle ORM 0.45 + dual Postgres driver:
  - `DATABASE_URL` set → `postgres-js` (Neon on Vercel).
  - unset → PGlite (Postgres 16 in WASM) at `./.pglite-data`. **Key decision:**
    no Docker/Postgres existed on this machine, and provisioning Neon needs a
    Vercel account, so PGlite makes the prototype cloneable with zero setup
    while keeping real Postgres semantics.
- exceljs for the export, recharts 3 for the dashboard.

### Source data findings (from `MIS Data Sheet _.xlsx`)
- Sheets: Tracking, Annual Target (131 SEEDS rows), Monthly Target (8 ACTB rows),
  plus an unused empty "New Activity" sheet.
- **Tracking has no actual entries** — rows 4–134 are a blank template with only
  Date/Month/Year/Project filled. It defines the *export format* only.
- **Activity code is not unique**: all 131 SEEDS rows carry `SEEDS-2024`; the
  per-activity key is the `sl` serial. Uniqueness = `(project_id, serial_number)`.
- Header row is row 3 (rows 1–2 hold a stray "Date:" annotation in column I).
- `Annual Target` / `Annual Budget` are empty for all 139 rows → exported blank.
- Header quirks preserved: `Varience` (sic), trailing spaces in `Project Name `
  and `Annual Target `.

### Verification (this is the part that mattered)
Built a CDP harness (`/tmp/rdrs-qa-harness.mjs`) that runs `next build` +
`next start` and drives real Chrome. **37/37 checks pass**, clean server log.
It caught a real bug that type-checking and a clean build both missed:

> Exporting a plain object (`initialEntryState`) from a `"use server"` module
> throws at runtime: *"A use server file can only export async functions, found
> object."* It surfaced only when the action was invoked, as an opaque
> "Application error". Fix: state types/constants now live in
> `src/lib/action-state.ts`.

Also verified separately with openpyxl: the export's 31-column header row is
byte-identical to the source Tracking sheet (incl. trailing spaces and the
`Varience` misspelling), number formats match, `Total` equals the sum of the nine
counts on every row, and dates render with no timezone day-shift.

### Environment gotchas hit (see the sandboxed-web-app-build-qa skill)
- `create-next-app` and `npm install` fail with `CODEBUDDY_BROKER_DENY`; run them
  with `NODE_OPTIONS=` and `dangerouslyDisableSandbox: true`.
- Chrome needs a **unique `--user-data-dir` per run**; reusing one silently hands
  the debugging port to a stale process and every CDP command times out.
- PGlite leaves `postmaster.pid` behind when a process is killed, deadlocking
  later runs. It always contains the sentinel `-42`, so it is useless as a
  liveness signal — added our own lock file with a real PID
  (`src/lib/db/pglite-lock.ts`).
- PGlite keeps the Node event loop alive, so CLI scripts hung and got SIGTERM'd;
  added `closeDb()` and call it from every script.
